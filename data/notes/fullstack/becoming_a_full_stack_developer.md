# Becoming a Full-Stack Developer

You've done something most people never do: built a complete application, frontend to database. That's the core of full-stack development. This final lesson is about turning that spark into momentum.

## What you've actually learned

Take stock — it's a lot:

- **Frontend** — structure (HTML), style (CSS), and behaviour (JavaScript).
- **Backend** — logic (Python), data (SQL), and APIs.
- **The glue** — how the two halves talk over HTTP with JSON.
- **The workflow** — Git, projects, and deployment.

You're no longer learning *what* the pieces are. From here, it's about getting *fluent* and building bigger.

:::analogy
You've learned all the chords. Becoming a great developer now is like becoming a musician — not more theory, but playing songs, over and over, until it's second nature. Build, build, build.
:::

## Pick a "stack"

A *stack* is just a combination of tools that work well together. You don't need to learn them all — pick one and go deep. Popular beginner-friendly stacks:

- **Frontend framework + Node** — React with an Express/Node backend (all JavaScript).
- **Python full-stack** — a JavaScript frontend with a Flask or Django backend.
- **Batteries-included** — Django (Python) or Rails (Ruby), which give you a lot out of the box.

:::tip
Don't stack-hop. Beginners lose months jumping between tools chasing the "best" one. Pick a reasonable stack, build three real projects with it, and you'll grow faster than someone who dabbled in ten.
:::

## Build a portfolio of real apps

Your projects are your proof. Aim for a few **complete, deployed, full-stack apps**, each a little more ambitious:

1. A to-do or notes app (you've basically built this!).
2. Something with user accounts and login.
3. An app that uses a third-party API (weather, maps, movies).

:::quiz
Q: What's the most effective way to grow from here?
- Read about every framework that exists
- Pick one stack and build several complete, deployed projects *
- Memorise syntax for ten languages
E: Depth beats breadth. Choosing one stack and shipping real, finished projects is what builds genuine skill — and an impressive portfolio.
:::

## Habits that make developers

- **Ship finished things.** A small completed app beats a big unfinished one.
- **Read other people's code.** Open source is a free masterclass.
- **Build in public.** Share progress; it builds skill and a network.
- **Be consistent.** A little every day compounds fast.

:::key
You can build across the whole stack. Now **pick one stack, build several complete projects, deploy them, and share your work.** Consistency and finishing — not chasing every new tool — are what turn a beginner into a developer.
:::

## Talk about it

Set your direction out loud:

> "Which stack will I focus on, and what's the first full-stack app I'll build and deploy?"

## The journey continues

There's no finish line in this field — and that's the joy of it. You started not knowing how a web page works. Now you can build complete applications. Keep going, keep shipping, and keep sharing. The web needs what you'll build. 🚀
